# v43 Windows Release inventory proposal

`inventory_v43.py` produces the current v43 schema-version-2 JSON receipt for a clean Release install tree. In addition to `files`, the current contract requires `directories`: every non-root install directory, including empty directories, as a normalized relative POSIX path. The list is bounded by the install entry cap and sorted by case-insensitive path order, with exact path spelling as a tie-breaker; case-colliding paths are rejected. This explicit list preserves empty directories that cannot be reconstructed from file paths alone. Older schema-version-2 receipts without `directories` use an earlier contract and are rejected by the current v43 adapter; keep them as historical evidence and write new receipts to new filenames.

The producer hashes every installed regular file, requires each project-built `.exe` to match a unique same-name executable in the explicit Release build tree, and uses the explicitly supplied `dumpbin.exe` to list each installed executable's PE DLL dependents. It requires exactly one copy of each CMake-installed project target at its expected `bin` path: `fea.exe`, `fea-solver.exe`, `range-control-velocity.exe`, `range-mesh-worker.exe`, `range-model-command.exe`, `range-project.exe`, `range-native-results.exe`, `range-workflow-native.exe`, and `range-workflow-isolation-launcher.exe`. A relocated or duplicate target path fails. Supplier mappings are forbidden for these basenames anywhere in the install tree, including case variants, repeated `.exe` suffixes, and Win32 trailing-dot/space aliases. Each installed target must match a unique same-name Release peer.

Optional `--link-map` input must be the `fea.map` beside the exact Release `fea.exe` peer. The producer binds both executable hashes to the installed inventory and checks the standard MSVC map sections plus the expected TetGen object symbols. It reports the map as `SUPPLIED_UNREVIEWED`; it does not claim the object graph has been independently reviewed. Optional `--gui-runtime-receipt` must be a schema-v2 installed GUI harness receipt for the same installed `fea.exe` hash and must be accompanied by `--gui-harness-script`. The producer verifies the supplied script path/hash against the receipt, rehashes its `stdout.txt`, `stderr.txt`, and `application.log` within the evidence directory, and validates the asserted paths of Qt Core/Gui/Widgets and `qwindows.dll`. Startup, normal-exit, and load-error fields remain unsigned local assertions. It reports `UNSIGNED_RECEIPT_QWINDOWS_ONLY` and requires independent review of the recorded harness script and raw logs before accepting execution as runtime evidence. It does not infer whether other plugins loaded, and it does not qualify a clean account or model-to-report workflow.

The v43 install rule directly copies `bin/openssl.exe`; if that file is installed, it requires an explicit `--supplier-exe` mapping to a source file and expected SHA-256. Any other installed executable that has neither a supplier mapping nor a unique Release peer fails provenance.

The inventory fails if it sees a `libomp` path or import; if `fea.exe` or `fea-solver.exe` is missing a `VCOMP140.DLL` import; if the package does not contain exactly one `vcomp140.dll` with bytes matching `--redist-vcomp`; or if it misses an expected packaging record. Expected records are the five Qt supplier notices, the 71 Qt 6.11.1 attribution pages selected by the v43 install proposal (including the nine qtpdf/PDFium pages for the deployed Qt PDF library and image-format plugin), at least one file under the Qt SDK SBOM directory, and `doc/licenses/TetGen/LICENSE`. With `--variant OFF`, path names containing `agent` or `range-ai` are checked for executable, library, object, script, and UI/resource suffixes; documentation paths are reported separately. Any installed `AGENT_OPERATIONS.md` file must be absent in OFF, matching the current conditional install rule. Embedded strings, linked object contents, and runtime-loaded plugins are outside this path check.

The command requires Python 3.8 or later. Pass the root of a multi-configuration build tree that contains a `Release` path component, or pass the Release configuration directory itself. Project-built executables must have exactly one same-name peer in that Release scope, with matching size and SHA-256. For each supplier executable, the receipt records its install-relative path, source path, operator-supplied expected SHA-256, observed source SHA-256, and whether installed bytes match the source. Obtain the expected hash from a trusted supplier manifest or separately verified source record; the script verifies the supplied value but cannot establish its trust origin. Immediately before and after every `dumpbin` call, the script rehashes the installed executable and requires both hashes to match its original inventory hash. The initial install scan records the complete `directories` list alongside `files`. After all dependency reads, it re-enumerates the install tree and rehashes every file, failing if any file or directory was added, removed, case-renamed, or changed; this includes empty directories. The parser requires the regular `/DEPENDENTS` section and accepts the optional delay-load section through `Summary`; all names from both sections are reported and checked. DLL names containing spaces or Unicode are accepted using the process locale encoding, while undecodable output and unrecognized section entries fail closed.

Neither scanned tree can contain symlinks, junctions, other reparse points, special files, case-colliding install paths, or paths/files beyond the safety bounds: 50,000 install files, 100,000 install entries, 20 GiB of installed bytes, 10 GiB per file, 1,024 characters per relative path, 128 directory levels, 200,000 build entries, and 1 TiB of build files. File and entry caps are enforced while iterating, before unbounded collections are built or sorted. Absolute input paths are limited to 32,767 characters. Pick a new output path outside the install tree; existing output files are never overwritten.

Example PowerShell command (replace every placeholder with paths from the v43 build and selected Visual Studio toolset):

```powershell
py -3 .\inventory_v43.py `
  --build-root "D:\path\to\fresh-v43-build" `
  --install-root "D:\path\to\fresh-v43-install" `
  --variant OFF `
  --redist-vcomp "C:\Program Files\Microsoft Visual Studio\2026\Community\VC\Redist\MSVC\<version>\x64\Microsoft.VC<version>.OPENMP\vcomp140.dll" `
  --dumpbin "C:\Program Files\Microsoft Visual Studio\2026\Community\VC\Tools\MSVC\<version>\bin\Hostx64\x64\dumpbin.exe" `
  --supplier-exe "bin/openssl.exe" "D:\path\to\OPENSSL_ROOT\bin\openssl.exe" "<trusted-sha256>" `
  --link-map "D:\path\to\fresh-v43-build\Release\fea.map" `
  --gui-runtime-receipt "D:\path\to\evidence\runtime-receipt.json" `
  --gui-harness-script "D:\path\to\qualify_installed_gui_runtime.ps1" `
  --output "D:\path\to\inventory-v43-off-v2-directories.json"
```

Use a fresh output path for the current `directories` contract. In particular, do not overwrite or relabel an existing ON receipt created before this field was added; its original bytes and hash remain historical evidence, and this producer refuses to overwrite existing files.

Repeat `--supplier-exe INSTALL_RELATIVE_PATH SOURCE_EXE SHA256` for any other supplier executable. Do not map any CMake-installed project executable basename listed above, even if the file was moved elsewhere; each target must remain at exactly one expected `bin` path and have a unique matching Release peer. Duplicate mappings, noncanonical Windows path components, and mappings that do not match an installed executable fail closed. If the install does not contain `bin/openssl.exe`, that mapping is not required.

The caller is responsible for using the same v43 Release build that produced the clean install, and for choosing the correct Visual C++ Redist file from that toolset. This proposal does not run against any live install. It does not assume a fixed total file count or a versioned prior install path.

Run the synthetic tests from this directory:

```powershell
py -3 -m unittest -v test_inventory_v43.py
```

The tests use temporary files with synthetic PE bytes and an injected dumpbin runner. They cover successful inventory, explicit sorted directory records including an empty directory, final whole-tree detection of added/removed empty directories and file additions/removals/mutations, missing or Debug-only executable peers, the required OpenSSL source mapping and hash, executable mutation during dumpbin, regular and delay-load dependencies including malformed sections and `libomp` exclusions, spaced and Unicode dependency names, fail-closed dependency parsing and text decoding, bounded directory enumeration and file counts, `libomp` files/imports, matching and mismatched map evidence, GUI receipt/module/harness/raw-log binding, missing Qt notices/pages, Agent OFF artifact and documentation checks, Redist byte mismatch, and use of the explicit `dumpbin.exe` path. They do not parse a real PE image or run a real dumpbin process.

`inventoryStatus: PASS` means only that these byte, path, and static import checks passed. Without `--link-map`, the receipt reports `INCOMPLETE_LINK_MAP_NOT_SUPPLIED`; with a matching map it reports `INCOMPLETE_LINK_MAP_REVIEW_REQUIRED` until independent review. Static imports do not establish which Qt plugins load at runtime; a GUI receipt records only the modules observed by its bounded harness. Presence and hashes of supplier material do not establish legal clearance or a mapping from every deployed component to its license.
