# GUI、Agent 与扩展工作流契约

状态：2026-10-03 工作流设计与分阶段交付契约。下列条目只有在对应实现、测试和交接证据齐备后才算交付。最新指令为收尾额度中断处工作并退出；Stage 10C、11、12 保留为后续计划，不能将本文设计描述当作已实现。实际证据见 `../HANDOFF.md`，既有数值支持范围不因此扩大。

## 1. 操作链与模块边界

工作流顺序为模型快照 → 分析/控制配置 → 预览 → 执行 → 接受结果 → 对照/报告；长任务具有排队、运行、成功、失败和取消状态。先以已验证四杆算例完成整条路径，再扩展已有梁功能。

- `range-application-lib` 继续拥有原生模型配置的校验与候选事务；现有 `range.application/v1` 保持兼容。
- 新工作流服务提供版本化 JSON 查询、命令目录、预览与任务接口。GUI、Agent 与 Python SDK 调用同一服务，不各自实现参数校验、文件发布或求解命令拼接。
- GUI 保持现有模型、求解和非结构功能，增量加入工作流/Agent 面板及上下文桥接；长任务不得阻塞 GUI 事件循环。
- Agent 查询当前能力与上下文，再提出结构化调用。模型回复是不可信输入，必须经过严格 schema、目录、版本和资源限制校验。
- 逐时间步控制仍使用现有 NDJSON v1/v2；工作流协议负责启动、管理和解释计算，不进入有限元 trial 或线性求解器内迭代。

## 2. 标准接口必须表达的语义

每个接口声明协议版本、操作 ID、精确参数字段、单位、只读/修改属性、前置条件、输出及错误码。未知操作、未知字段、非法数值和过期模型必须明确拒绝。

模型身份、单调会话 revision 和文件 SHA256 各有职责：身份绑定当前会话；revision 绑定编辑顺序；SHA256 绑定实际文件内容。关闭/重新载入后旧请求失效；Undo/Redo 产生新版本，不复用旧批准。

修改流程必须先生成规范化预览与摘要，批准绑定具体内容、来源模型和版本；执行时再次校验。Agent 可提出预览，不能通过回复字段自行生成批准。宿主 GUI 的明确批准操作与 Agent 工具目录分离。CLI/SDK 的宿主可在明确授权的批处理范围内批准；这不是远程认证或多用户权限系统。

重复请求不能重复启动任务或发布输出。修改中的模型不能同时用于配置提交；长任务使用不可变输入快照。取消或失败可以保留诊断和部分中间文件，但不发布可被误认为成功的新结果。

## 3. 审计与发布

预览、拒绝、批准、接受、开始运行、失败/取消、文件发布分别记录。记录关联 actor、命令摘要、前后 revision、run ID 及实际工件路径/SHA256；不得记录 API 凭据。尽可能沿用 `InteractionRecord v1`，额外索引作为版本化存储元数据。

先构造候选并确认审计可写，再提交修改；磁盘状态采用单文件原子发布或明确的恢复协议。日志写失败不能静默报告操作已完整成功。模型文件、任务状态和审计若不是一个磁盘原子事务，必须定义并测试中断恢复，不能只凭内存回滚推论。

## 4. Agent 工作流

Stage 11A：当前模型/能力/任务/结果查询，诊断解释，修改预览。Stage 11B：宿主批准后执行、有限步骤/时间预算、取消和失败报告。现有多供应商 `RAgent` 作为可替换的文本推理端，结构化工具桥接负责执行；测试使用确定性模拟回复，实际远程模型验证单独记录。

侧栏展示当前工作阶段、模型/运行来源、对话、待执行内容、批准/拒绝按钮和任务结果。上下文只发送完成任务所需的配置、目录与摘要；完整大向量、秘密信息和无关文件不自动加入。

## 5. 版本化 SDK 与受控扩展

Stage 12A 先提供进程外 Python 客户端、握手/能力发现、错误映射、示例与契约测试。不得把内部 C++ 头文件或未设计 ABI 宣布为稳定插件 SDK。

Stage 12B 首个扩展必须有实际用途并通过正式入口运行。流程为能力缺口 → 扩展需求/输入输出 → 生成候选源码和测试 → 隔离目录校验 → 展示源码差异与验证结果 → 宿主批准固定内容哈希 → 注册/进程外执行 → 结果及审计。失败候选可归档/清理，不能覆盖已激活版本。

扩展清单至少声明 ID、版本、SDK 协议、扩展类型、输入输出和源码/测试哈希。批准和测试结论都绑定相同内容；源码变更后必须重新验证批准。执行有超时、输出大小和并发限制，使用可控 argv，不拼接 shell 命令。进程隔离和临时目录不等于操作系统安全沙箱；任意生成代码执行前必须由宿主明确授权，不在生产 GUI 进程中动态加载。

## 6. 验收顺序

1. 10A：真实 GUI Session 基线操作；模型生命周期与审计；变更后重跑窗口/保存重开/旧请求拒绝。
2. 10B：四杆配置、实际 FE 主动/被动对照及独立参考；同一流程的续算、取消和失败恢复。
3. 10C/11A：工作流面板和只读 Agent 可并行集成；11B 在批准、版本和审计贯通后验收。
4. 12A：干净进程 SDK 客户端使用相同能力目录和契约；12B 验证一个从生成到激活使用的实际扩展以及失败/篡改/超时反例。
5. 全目标 Release、必跑测试清单、完整 CTest、安装树及独立审查；干净 Windows、远程 CI、远程模型或硬件未测项保持独立声明。

每个里程碑更新开发计划、交接和提交；不能用模拟 Agent 回复代替真实工具执行，也不能用单元测试代替实际 FE 或完整 GUI 链路。
