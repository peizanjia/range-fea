# 持久任务计划与版本化操作知识

对应WF08当前实现；完整验收状态以workflow_delivery_plan.json为准。首批计划使用已登记并配置的原生杆／梁来源，创建只保存经过验证的步骤，不启动作业或批准写入。

## 创建与运行

先在Experiment选择当前文档的已登记快照，预览并配置其工作区。Task plans两点扫描保留这个来源，指定两个目标阻尼比和接受步数。Create two-point scan创建configure→run(both)→独立误差条件的固定计划；Start开始调度。

每个配置或运行节点单独等待批准。选择节点，核对来源及时间步、步数、阻尼比的宿主前后值，再点击Approve selected node preview。批准只覆盖当次固定预览；模型可以提出候选计划和读取状态，不能代替用户批准。

任务树显示节点宿主状态、输入和实际作业引用。提交接受只证明作业已登记；完成还须核对来源、配置、原生工件及独立数值验证。退出0或模型文字不能使节点通过。

首批验证逐一检查主动／被动结果、接受步数、manifest/文件SHA和独立末态误差：平移／转角≤1e-8 m/rad，速度／角速度≤1e-7 m/s、rad/s。这个谓词声明末态与原生工件验证范围，不扩展为任意非线性模型或全轨迹误差保证。

## 暂停、取消与恢复

Pause plan暂停新增节点，已提交计算保持独立。Cancel plan及接替同样不隐式取消作业；取消具体作业使用其独立操作。条件、澄清、批准、暂停和未知结果由宿主保存。

重开后未提交预览和批准失效；已登记作业先核对原job／execution收据，不能重复提交。未知结果停止自动重试。来源、配置、能力、环境或知识不匹配报告冲突，重新核对和预览。

continue-independent只允许不依赖失败节点的步骤继续；依赖必需校核的节点被阻塞。必要节点失败时计划不能完成。条件只使用有单位、有限的宿主标量，拒绝任意表达式或Python代码。

## 明确上限

每计划64节点、每节点16依赖、固定扫描4点、候选JSON128KiB；工作区保留16计划。只读最多2个并行，写步骤串行且校验资源依赖。

执行模型调用24、工具128；每节点模型4、工具16。当前确定性调度器不进行模型调用；等待由宿主作业状态变化驱动。活动预算1800s、每节点300s、总deadline24h；暂停／等待不计活动预算，仍计总deadline。恢复不清零计数。

## 知识与SDK

knowledge.query只检索随包封闭registry，绑定当前发布能力、schema、包版本／哈希和适用状态。签名、单位与权限来自运行时代码；知识、示例和历史不增加权限。AGENTS、SKILL、HANDOFF及开发playbook不进入产品检索。

SDK提供propose_plan、plans、control_plan、approve_plan_node、answer_plan。随包examples/parameter_scan.py必须提供用户批准回调，拒绝或超时暂停，不默认自动批准。批准API属于受信调用者，不能由模型代码或知识文本自行取得。

存储v3兼容迁移v1/v2，节点接受和作业ledger在同一原子状态提交；不声明加密或OS隔离。普通模式生成代码执行仍等待WF12证据。
