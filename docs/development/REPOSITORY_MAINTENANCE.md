# 仓库维护规范

根目录的 [AGENTS.md](../../AGENTS.md) 给后续 Agent 提供执行入口。每轮开始先确认工作目标、当前分支及上游、已有改动、暂存区和子模块状态。并行任务先划分文件归属，独立任务优先使用独立工作树。

## 文件保存位置

| 内容 | 位置 |
|---|---|
| 产品代码、测试和可复用测试夹具 | `src/` 中对应模块 |
| 持续使用的检查、打包和验证工具 | `scripts/ci/`、`scripts/packaging/`、`scripts/benchmark/` 对应工具组 |
| 当前接口、操作手册和通用开发规范 | `docs/reference/`、`docs/development/` |
| 单轮目标、设计、决定、验收摘要和交接 | `docs/rounds/<日期>-<目标>/`，沿用同目标目录，并更新该轮入口 |
| 跨轮复盘和原始开发日志 | `docs/history/` |
| 本机计划、进度、发现 | `.planning/<任务>/` |
| 构建和编译输出 | `build/<配置或任务>/` |
| 原始日志、测试结果、截图、隔离配置、临时工具和运行时 | `artifacts/<任务或运行编号>/` |

根目录用于入口、许可证和工具约定要求固定位置的文件。冻结合同等路径例外要在文档索引记录理由。新增目录按用途和任务命名，续作沿用原目录，重复运行在任务下使用新的运行编号。可移交的验收摘要应记录源码版本、平台、执行范围、结果及证据定位。

## 运行与清理

启动前核对临时路径、应用配置、缓存和输出均解析到当前仓库内。一次性脚本放在对应运行目录。每次运行结束以及任务交接前，核对文件引用、可再生成性及进程归属，删除本轮已失效的临时脚本、展开副本、缓存和废弃构建。保留可复用构建、仍被使用的运行时以及复验需要的模型、日志和收据。压缩归档时先比对成员，再移除展开副本。交接时说明删除、归档和保留的项目。

## 分支与提交推送

- `main` 是集成分支，按项目约定合入。`feature/structural-profile` 是现有结构开发线。接续该线时沿用现有分支。独立的新任务通常从约定的基线创建 `codex/<任务>` 短期分支，合入后按团队流程清理。
- Agent 在形成可审阅的阶段成果时主动提交和推送，交接前检查是否还有已完成但未发布的成果。自动执行由每轮 Agent 在这些节点发起。用户要求只读、暂停、仅本地保存或指定目标分支时，以该轮指示为准。
- 先核对差异、测试结果、文件所有权、凭据及大型产物，再按文件或差异块暂存，检查暂存区。预先存在的工作、用户改动、其他任务和子模块改动须另行确认归属。临时输出使用忽略规则，保留 Git 中的可移交摘要。
- 核对远端和目标分支。已有上游时推到该工作分支。新工作分支首次发布时明确远端并建立跟踪。远端领先、分支受保护或推送失败时保留本地提交，报告原因及实际同步状态。需要更新子模块时，先在子模块发布并确认目标提交可取，再提交主仓库指针。
- 在任务交接中记录提交号、推送目的地、通过和未验证的检查，以及留在工作区的改动。涉及真实安装、系统或数值验收时，按对应轮次的标准记录。
