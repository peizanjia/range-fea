# 会话、分支与旁路只读问答

本文对应当前 WF-07 实现，验收状态以 workflow_delivery_plan.json 为准；当前仍在整体验证，不声明完整产品或外部干净 Windows 已交付。

## 选择正在进行的工作

- **Send / Send now**：向主任务发送追问或接替指令。旧模型回合和未执行提案失效；已经提交的计算由自己的作业状态继续管理。
- **Read-only question**：把当前输入作为独立问题打开旁路窗口，主提案、输入草稿与已提交计算继续保留。旁路不允许准备提案、批准、执行、生成代码、注册来源或打开结果文档；Auto 不可开启。
- **Stop**：只停止所在窗口的模型工具链。求解器作业的取消是另一项绑定具体作业的操作，不能由模型文字或历史消息代替。

每个窗口有自己的 task/request/generation 和输入。旁路只在来源版本核对后发布完整回答；主窗口仍支持流式文本。来源修改、关闭或工作区变化时，旁路旧回答拒绝发布，重新提问会取得新的来源。历史作业进度可以变化，但其工件与来源必须仍可校验。

## 历史与分支

桌面主窗口可恢复该项目上次选中的会话；独立嵌入组件默认开始新会话。Saved conversation 选择历史；Earlier / Later 每次读取最多 50 条。页面中的宿主事实保留可核对的操作、作业和来源引用。

Branch 以所选历史消息为边界创建独立会话和消息身份。已经发生的修改保留为历史事实；分支不会重复提交原作业，也不会复制批准、未执行提案或自动执行权。分支重新发送时取得当前上下文并重新预览所需操作。

供模型使用的历史摘要最多 12 条，每条最多 2000 字符；优先保留当前页的历史事实。完整原消息仍可分页查看和导出。摘要是历史数据，不能作为当前状态、操作授权或数值成功证明；工件缺失时需重新查询，不得补造结果。

## 执行结果核对

在提交动作前，会话先保存未知结果的核对引用。接受结果按原 task 和会话追加；接替或取消不会把迟到结果改记到新任务。

- GUI 的 `operation.query` 可用原 `idempotencyKey` 查持久观察。
- 工作流的 `execution.query` 可用 `requestSha256` 查接受收据，并核对原 `workflowProjectId`。

这些引用不是批准令牌，不授予重试或执行权。收到拒绝按拒绝记录；结果不确定则保留待核对状态。重开会话可执行只读核对，不自动执行旧提案。接受提交也不等于数值作业成功，实际终态和结果要通过作业／原生结果接口查询。

## 导出、删除与存储边界

More → Export conversation 导出已验证的可见消息、宿主事实及引用，不包括模型私有协议历史或执行权限。Delete conversation 删除该会话的已验证存储，独立分支和真实模型修改／作业保持原状态；删除聊天不会撤销动作。

存储位于项目 `conversations/`。记录版本化、不可变、带哈希与独占提交标记，协作写入使用锁。损坏的已提交记录拒绝读取并保留；未提交残留可诊断，不能充当有效历史。工作区及路径需符合已登记项目身份，不能通过链接跳出管理目录。

当前上限：每会话 512 条、单条文本 16 KiB、每页／追加最多 50 条、每项目 32 个有效会话、每会话 20 MiB、项目会话存储 128 MiB。未解决执行引用预留结果条数和每条 8 KiB 空间；普通消息不能消耗该预留。超限明确拒绝写入，不删除旧证据来制造成功。

只存显式可见 user/assistant 消息、白名单宿主事实和受限引用；不存 system/tool 原始历史、私有 reasoning、批准令牌、待执行指针或供应商错误正文。已知敏感字面值和凭据赋值在保存前脱敏。这里不声明存储已加密或具有 OS 沙箱；任意未知自由文本的敏感性仍需用户谨慎判断。
