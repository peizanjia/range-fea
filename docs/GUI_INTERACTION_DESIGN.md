# Agent 与动力学控制交互设计

更新：2026-10-04。本次在 Stage 10C–12 受控 v1 基线上改进日常交互，数值能力和扩展执行边界仍由能力注册和验收文档限定。

2026-10-08 已将第 5 节及跨模块缺口拆入 [全工作流交付方案](WORKFLOW_DELIVERY_PLAN.md)。本文保留交互原则；后续状态和验收分别以 JSON 清单及 WF 条款为准。

## 1. 工作区布局

- **中央模型视口**：几何、选择、结果可视化，修改仍通过现有文档事务和 Undo/Redo 更新。
- **右侧 Assistant**：独立可停靠面板，与模型属性面板切换；对话占主要空间，输入框固定在底部，不跟随整页滚动。
- **底部 Dynamics & control**：独立宽面板，分为 Live monitor、Experiment、Results & history。配置和历史不挤占实时曲线。
- **Application settings → Agent**：供应商、端点和会话凭据；侧栏保留模型、effort、权限这些每轮交互选项。
- **Panels 菜单**：恢复被关闭的面板；停靠位置通过原窗口设置保存。

## 2. 对话状态与操作语义

| 用户动作 | 运行语义 | 界面反馈 |
| --- | --- | --- |
| 发送第一条消息 | 查询当前宿主状态，建立受限工具任务 | 用户消息、当前状态、模型回应 |
| 完成后追问 | 保留有界的会话数据，重新获取当前上下文和授权范围 | 同一对话继续 |
| 工作中 Send now | 使旧请求、旧问题和旧提案失效，依据新要求开始一轮 | 输入始终可用；计算任务继续由工作流管理 |
| 模型提问 | `ask_user` 返回问题和有限选项，暂停这条工具链 | 问题卡片；选择或自由输入回复 |
| 批准/拒绝 | 仅宿主接受当前 proposalId；聊天文字不等于批准 | 行内操作卡片和实际结果 |
| Stop | 停止 Agent 后续步骤和网络请求 | 已提交计算不回滚；在工作流中显式取消 |
| New chat | 空闲时清除会话；不清除模型或计算结果 | 清空对话并重新开始 |

输入过程中不因状态刷新、事件轮询、批准或设置变化丢失草稿。每轮固定供应商、端点、模型、effort 和凭据，设置更新在下次发送时使用。自动执行只覆盖当轮明确授权的初始文档和工作区；扩展操作保持单独批准。

模型回答支持 Markdown 排版；禁用原始 HTML、外部/本地资源加载及链接自动打开。用户输入、问题卡片和操作结果保持转义纯文本，避免把显示内容变成执行入口。

会话历史是有界内存数据。历史工具结果用于解释发生过的操作，不充当新的权限或当前模型状态。发生冲突必须重新读取状态，拒绝的操作不得悄悄重试。中断后未返回的异步操作不能据此声称失败或未执行。

## 3. 模型适配

- 当前接入 DeepSeek 和兼容 Chat Completions 的端点，不宣称兼容任意供应商原生 API。
- DeepSeek 提供 Off、Low、High、Max；启用思考时发送 `thinking.type=enabled` 和 `reasoning_effort`，工具轮次保留供应商要求的有界 `reasoning_content` 协议数据，不把它显示为操作证据或普通回答。
- 其他兼容端点在没有能力声明时显示默认 effort，避免无效参数。
- 凭据仅驻留当前会话；不进入 QSettings、聊天上下文、日志和导出。
- 端点只接受不含用户信息、查询参数和片段的 HTTPS URL；非法输入保留上一有效设置，避免把 URL 中的凭据写入磁盘。
- 本次按完整响应显示中间/最终消息，尚未实现逐 token SSE 流式输出。

参数依据：[DeepSeek 思考模式与工具调用官方文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)，2026-10-04 核查。

## 4. 原生控制监视接口

`range.workflow/v1` 的只读操作 `telemetry.query` 按工作区内固定任务的原生执行日志获取已接受步，不开放任意文件读取：

```json
{"operation":"telemetry.query","parameters":{"jobId":"...","mode":"active","afterSeq":0,"limit":256}}
```

响应包括任务/运行身份、任务状态、`source=native-accepted-control`、序列游标、是否有下一页及样本。样本携带接受状态时间、传感器值与单位、实际施加的力/功率/累计功。时间采用接受状态的仿真时间，不用墙上时间伪造数据。

界面按游标获取增量，单请求上限和显示缓冲有界；切换任务丢弃旧任务迟到响应。没有控制通道、尚无样本、连接中断及校验失败均明确显示，不能补零冒充数据。

监视区显示传感器与施加力两幅曲线，支持通道选择、全时间或最近时间窗口、自动纵轴、鼠标读值、Hold display 和 CSV 导出。Hold 只冻结图像，继续收集样本，不能被解释为求解器暂停。CSV 记录任务、运行、事件序列、时间、通道和单位。

独立 Newmark `reference.json` 是另外一条验证路径，不是原生求解实时曲线。普通文档求解快照、独立杆/梁控制工作区、参考校验和扩展运行分别标识；界面不把它们合并成未经验证的功能。

## 5. 后续商业产品质量路线

本次优先交付上述可实际运行、可验证的交互闭环。下列能力需独立增量及验收，不能以界面相似替代完成：

1. **对话体验**：有界 SSE 流式解析、任务树与工具活动卡片、可恢复会话列表、编辑重发和分支、跨任务只读即时问答。持久化前明确脱敏、保留策略和恢复后的批准失效规则。
2. **控制工作台**：多任务叠图、参考对照误差曲线、频域/相图、布点与通道映射、布局保存、长时数据降采样和多轴单位检查。图表不得改变求解时间步。
3. **实验交互**：如需运行中调参，先定义 accepted-step 参数提交事务、可改参数能力表、时间戳和回滚/拒绝语义；当前配置新实验或续算不等同于任意运行中改控制律。
4. **二次开发**：统一声明式表单/图表扩展接口、能力发现、版本迁移、任务固定版本、自动生成测试与审查差异；普通用户执行任意生成代码需要实际 OS 隔离方案，当前受信模式不能替代。
5. **产品验收**：键盘与屏幕阅读器、窄窗口/高 DPI/深浅主题、断网重试与任务恢复、长对话/长时序性能、干净机器安装分别设门槛；不凭一张截图宣称达到某商业软件的全部水平。
