# WF14 GUI mesh worker checkpoint

2026-10-09. Bounded GUI controller/widget source implementation; not WF14 acceptance. This agent did not run a native build, QtTest, or mesher because the root owns the serial native validation window. Root must integrate the files, trusted host bridge, nonqueued Session append, required tests, native execution/rebinding gate, workflow page, and installation.

`MeshJobController` owns GUI-thread captures, a workspace lease, a registry limited to 64 retained attempts, explicit ephemeral generation/acceptance previews, one active native worker, a cancellable queue, and independent artifact reconciliation. `MeshCommandWidget` receives the shared host-owned controller through `setController`, displays separate preview/approval buttons, validated volume/radius options, source/job identities, phase/state/stale-source status, and read-only quality/receipt details. There is no percentage estimate. Approval methods are plain C++ trusted UI/host entry points, not invokable operations or caller-provided durable tokens.

Source capture uses `Session::createDocumentSnapshot`, which requires a synchronized project identity and resolved numeric drafts. The immutable native catalog snapshot is copied into `mesh-jobs/captures/<UUID>/source.rbm`. A separate runtime JSON file, source snapshot ref, documentId/sessionEpoch/revision, full native SHA256, supported-command-state SHA256, and any loaded native source-chain artifact hashes are retained. `RMeshJobService::prepare` creates the exclusive `mesh-jobs/attempts/<UUID>/request.json`; controller state stays outside that worker-owned directory. Only the fixed executable beside the GUI can be launched. Source, request, runtime file and worker hashes are checked before launch; the service verifies them again in the actual worker and during candidate reconciliation.

Windows launch uses `STARTUPINFOEX` with `PROC_THREAD_ATTRIBUTE_JOB_LIST` and `HANDLE_LIST`, `CREATE_SUSPENDED`, and a configured `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` Job object. Membership is checked before resuming the primary thread; assignment is atomic at creation, including the owner-crash interval. Only an explicit inherited NUL IO handle is passed. Fixed limits are 512 MiB per process, 768 MiB for the tree and 180 seconds wall time. Unsupported Windows Job-list creation fails closed; there is no weaker process-launch fallback. Cancellation first terminates the Job tree, remains `cancelling`, then becomes `cancelled` only after the process handle is signalled and Job accounting reports zero active children. Owner close retains `interrupted` or `interrupted_unknown`, kills the Job and never silently reports cancellation. Restart never launches queued/interrupted attempts or repeats acceptance. A complete artifact receipt can independently reconcile to `candidate_ready` without acceptance authority.

Candidate readiness requires `RMeshJobService` native-byte/quality/source/context/worker verification. Acceptance previews bind the verified candidate/report receipt and the exact source identity. Approval rechecks full live source serialization, original saved source bytes and all candidate hashes. The root-owned `Session::appendMeshCandidate` must publish atomically on the GUI thread, fail immediately on a busy mutex, recheck source identity and supported state under that mutex, and return the actually appended model ID. The candidate becomes a new unsaved native document with its `TASK_NONE` and cleared mappings intact; the source and existing results are preserved. An intent is persisted before append, and persistence failure after a successful append reports an unknown durable receipt rather than retrying. Closed/changed sources retain the independent candidate but cannot use the current-source acceptance mode. No automatic independent-source acceptance or overwrite mode exists.

New test source covers exact options/pure preview, separate approval, queued cancellation without worker intent, actual worker candidate/review/new-document acceptance, source preservation and fresh identities, `TASK_NONE`, no loaded source provenance, stale/closed source refusal, candidate tampering, unannounced full-source mutation, visible input invalidation, actual running cancellation/tree-exit confirmation, owner close and no restart replay. These checks are authored but unrun pending root registration/window. They require the actual fixed worker beside the GUI test executable. Descendant fault injection, hard memory/time exhaustion, installation, shared agent host routes, native solve and complete static-rebind workflow remain integration validation.

The existing TetGen dependency remains the mesher. This implementation adds detached orchestration and verification boundaries; it does not claim an independently authored meshing algorithm or clean-room provenance.

## Review 3 repair checkpoint

The root's first GUI controller run timed out after 180.03 seconds in `previewAndQueuedCancellationLeaveSourceUntouched`, before its first pass. This is a failed validation attempt. Read-only diagnosis found that the normal source-import material manager asks about unknown fixture materials synchronously. The revised test setup requires Qt test mode and the isolated `test-runtime` material directory, writes one exact fixture material there, refreshes the real material tree, and removes that file at test cleanup. Main-window mesh widgets temporarily release their controller reference so their background refresh cannot contend with test-owned workspace leases; the host reference is restored at cleanup. The production import policy is preserved.

Cancellation and wall-time expiry now write a separate hash-bound `captures/<attemptId>/owner-decision.json` before terminating a Job. A failed registry write is returned as `valid:false`/`cancel_registry_unknown`; it never acknowledges durable cancellation success. Stop decisions remain sticky in memory and recovery, even if a complete candidate receipt exists. Timeout uses `timed_out` (or `timed_out_unknown`) rather than a generic reconcilable error. Legacy `worker_timeout` entries are suppressed as well. Restarted nonterminal states without a confirmed durable outcome become `interrupted_unknown`, which cannot be promoted by read-only reconciliation. A corrupted stop record also blocks candidate promotion. Child-tree exit must still be confirmed before live cancellation becomes `cancelled`; recovery with a nonzero historical PID remains unknown.

The Session append API now additionally returns the immutable created document UUID and whether publication may already have occurred. After synchronous `modelAdded` callbacks, the controller resolves that UUID afresh, verifies the original workspace/attempt/request identity, source runtime and complete native-byte proof, no draft or inherited provenance, and exact accepted snapshot SHA256 equality with the verified candidate file. Material changes, candidate removal, source mutation, workspace switching, or failed post-publication checks yield sticky `acceptance_unknown` with the created UUID. The original durable acceptance intent is retained; no old attempt is inserted into another workspace, no source is rolled back, and acceptance is never retried automatically. Failed append with `documentMayExist=false` alone remains a retryable refusal.

Additional authored regression cases cover a forced registry-path write failure with sticky queued cancellation across restart, timeout/cancel decisions winning over an actual completed worker receipt, direct publication callbacks that change materials/remove the candidate/switch workspaces, and removal of the seeded database material before verified candidate publication while retaining exact candidate material bytes. No new native build, QtTest or mesh execution was run by this repair agent; the root must run the next serial validation window.
