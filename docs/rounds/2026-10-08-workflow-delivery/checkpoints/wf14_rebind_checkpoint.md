# WF14 static physics rebinding checkpoint

`RMeshRebindService::preview(source, arguments)` produces a detached complete candidate. It does not approve, publish, invoke a mesher, or solve. Rejected calls return an empty candidate and never change source. Successful calls bind fresh explicit node conditions and uniform isotropic material before enabling the Stress task tree.

## Exact input

```json
{
  "unitSI": true,
  "staticStress": true,
  "material": {"youngModulusPa": 1000, "poissonRatio": 0.25, "densityKgM3": 1},
  "constraints": [
    {"nodePhysicalId": 101, "values": [0, 0, 0]},
    {"nodePhysicalId": 111, "values": [null, 0, 0]},
    {"nodePhysicalId": 121, "values": [null, null, 0]}
  ],
  "loads": [{"nodePhysicalId": 131, "forceN": [0, 0, -1]}]
}
```

Every object rejects unknown/missing fields. Physical IDs are exact existing nonzero integer node IDs; no nearest-node search or old mapping reuse. Each array contains 1..1000 distinct node IDs. Constraint XYZ entries are finite displacements in metres or null (disabled); at least one axis per constraint must be enabled. Forces use three finite numeric newton components and each force vector must be nonzero. The same node may have one constraint and one load; it shares one fresh point target. The service sorts arrays by physical ID without reducing numeric precision.

Bounds: 4..10000 nodes, at most 50000 elements including fresh POINT targets; absolute coordinates/displacements at most 1e6 m; absolute force components at most 1e12 N; E in [1e-12,1e18] Pa; density in [1e-12,1e12] kg/m^3; -1 < nu < 0.5 with finite positive shear and bulk moduli. This scope accepts exactly one face-connected linear TETRA1 region with its complete outward **convex** TRI1 boundary and unambiguous surface/volume membership. Invalid connectivity, duplicate IDs/elements/nodes, nonpositive/unresolved Jacobians, nonmanifold faces, same-side shared faces, disconnected bodies, and missing/duplicate boundary faces are rejected. Nonconvex or overlapping wrapped legacy meshes are outside this first scope, even if their local Jacobians and face incidence pass.

After the independent local topology checks, the service reconstructs a boundary-only detached shell, remapping only its temporary node positions, and calls `RMeshCandidateService::preview` without invoking a mesher. This reuses the established outward convex half-space, connected genus-zero, vertex-link and coplanar-overlap guards. Temporary synthetic IDs/labels identify eligibility geometry only; the original source IDs and all binding targets remain unchanged. Old materials are replaced with the same unused empty material in this geometry-only shell, because eligibility must not infer old physics. Shared shell limits are 5002 boundary nodes and 10000 boundary triangles. Preview arguments use SI units, radiusEdgeRatio=1.6 and maxVolume=clamp(boundary bounding-box volume,1e-15,1e18), keeping the backend estimate within the shared bounded profile; these arguments do not refine or certify the volume/quality of any current tetrahedron.

Every volume node, including interior nodes omitted from the temporary shell, must also lie in every inward convex boundary half-space at the existing relative plane tolerance 1e-10. This check is capped at 20000000 node/face pairs. The positive tetrahedron volume sum must equal the verified convex shell volume within relative tolerance 1e-8. Positive tetrahedron orientation, cancelling internal faces and the verified simple convex boundary restrict this entry point to a single physical region rather than allowing multiple overlapping wraps. Reports include `meshEligibility.scope=WF14_convex_single_region`, actual source boundary physical IDs, shared shell preview arguments/hash/volume, tetrahedron volume agreement, half-space pair count and verification flags, and `generatorInvoked=false`. This is a conservative convex first scope; it is not a general nonconvex intersection algorithm or a mesh accuracy certificate.

## Source and candidate invariants

The source must have a default NONE task tree, default-reset ProblemSetup and TimeSolver, empty restart state (including unavailable stale vectors), no BC/IC/EC, no variables/results, no monitoring/derived/entity mappings, and no Point/Line geometry. The only source setup exception is the exact two sizing seeds written by `Model::initializeMeshInput` during native load or Session import: the service independently scans every actual node coordinate, derives `volumeConstraint = bboxDx*bboxDy*bboxDz/1000`, `maximumSeed = cbrt(12*volumeConstraint/sqrt(2))`, and `minimumSeed = maximumSeed*0.1`, and requires exact equality to both finite positive retained values. These are bounding-box sizing seeds, not measured minimum/maximum physical mesh edges. After zeroing only these two fields in a detached setup copy, full native-byte equality to default ProblemSetup is still required; no arbitrary mesh option, rounded/toleranced pair, or stale solver/time/control state is accepted. The report records this proof in `meshEligibility.sourceSetupProof`, including the profile, origin, exact derived values, and full-default remainder verification. Candidate ProblemSetup remains completely default-reset, including zero sizing seeds. Default setup equality uses the current native binary serializers with a real opened RSaveFile inside a private automatically cleaned QTemporaryDir, then checks the committed bytes through QFile. This reversible verification IO never publishes an owned model file. A fake open QSaveFile without its file engine is unsafe and is not used. Old surface/volume materials are not inferred: the candidate clears them and assigns one newly constructed material only to the volume. The existing Stress property requirements also require a fresh explicit zero thermal expansion coefficient at reference temperature 293.15 K; this enables no thermal task or thermal load.

Each distinct bound node receives one new single-node POINT element and group through the source snapshot's current native allocators. Existing node/mesh/group identities are retained; all new element/group IDs are checked disjoint from source IDs. Allocator exhaustion rejects the entire detached candidate. POINT targets have no material or EC/IC. Native DISPLACEMENT/FORCE conditions use typed global XYZ components and one enabled sample at time zero, matching the existing entity.boundary.set representation. No boundary-face condition is reused.

The `RMeshSetup` ASCII writer now uses 17-digit precision only for its own record and restores the caller's previous precision through RAII. This preserves already initialized sizing seeds across new RAM saves and reloads; the binary format is unchanged. Historical RAM files with nonzero seeds rounded by the previous default text precision remain ineligible unless both retained values happen to match the exact current coordinate-derived pair. No tolerance or inferred repair is introduced for those files.

Legacy `clearEnvironmentConditions`/`removeAllEnvironmentConditions` restore gravity/temperature defaults. This service and its source fixture instead remove environment entries individually, including from every new POINT group; no implicit gravity load is introduced.

Six analytic rigid-body displacement fields are formed on all nodes: three translations and three `omega cross (x-centroid)` rotations. Geometry is centred/scaled; the six columns are twice reorthogonalized. Full-pivot elimination of the prescribed-axis rows requires rank six at relative tolerance 1e-10. Six component declarations alone are insufficient. Face-connected one-region eligibility is essential to this six-mode scope. This check removes rigid-body modes; it is not a stress accuracy, mesh quality, or general numerical conditioning certificate.

Successful reports derive from the actual detached candidate and include physicsState/bindingState BOUND_STATIC, requiresRebinding=false, new node-to-element/group targets, force resultant and moment about the global origin, constraint/load physical IDs, rank/tolerance, SI material values, and disabled control/dynamics/restart/ROM. The Stress task is enabled only after complete binding construction, followed by actual typed-condition/default-setup/rank checks. Source/post geometry hashes include the added POINT elements and groups. sourceStateSha256/postStateSha256 use the existing model-command supported edit fingerprint and are explicitly labelled `supported_model_command_state`; they are not full native-state/file hashes. Session/native authority must independently bind full source snapshots, document stamps/read sets, arguments, and owned deltas.

The trusted C++ `RModel::applyStaticMeshBindingCandidate` publication seam supports both approved forward binding and the authoritative delta's Undo/Redo. It independently checks the default-or-exact-sizing-seed setup profile on both models, identical common nodes and original TRI1/TETRA1 element/group identities and connectivity, and a canonical unique single-node POINT tail on the bound side. Preparation starts from the live model to retain GUI/source metadata; the required trusted callback checks the prepared accepted state before publication. The commit uses vector swaps and scalar writes, including explicitly nonthrowing sizing-seed setters; no whole-model assignment, allocation, serializer or callback runs during the commit. Undo removes only the owned POINT tail; Redo restores the delta's captured IDs. Element/group allocator high-water marks remain the maximum of live and candidate values, so subsequent fresh edits never recycle removed IDs. Lower historical IDs gain authority only from the existing validated delta and hash callback, not from raw protocol input.
