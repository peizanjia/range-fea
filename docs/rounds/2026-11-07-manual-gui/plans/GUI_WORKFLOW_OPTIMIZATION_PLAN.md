# Range FEA 手动工作流与界面优化执行方案

## 目标与边界

以用户亲手完成有限元任务为主线。助手关闭、未配置凭据或断网时，建模、设置、网格、求解、结果和导出都应可独立操作。优化以实际点击路径、窗口状态和结果正确性为证据。先观察当前软件，再确定修改项。本文件列出的操作节点是走查脚本，菜单名称、点击次数和截图由执行时实测填写。

复用 [界面设计记录](../../2026-10-01-application-agent-v1/design/GUI_INTERACTION_DESIGN.md)、[历史交互验收](../../2026-10-01-application-agent-v1/acceptance/GUI_UX_ACCEPTANCE.md)和[压电 GUI 操作矩阵](../../2026-10-12-piezo-delivery/evidence/piezo_gui_operation_acceptance_matrix.md)。历史矩阵已列出控件对象名、窗口、压电六个页面及验收条件，可以用于定位和复测。当前源码可确认左侧模型区、中央视口与输出页、右侧求解设置、底部动力学工作流及可停靠助手并存。不同工作区的使用频率、视觉拥挤和操作摩擦需在真实主窗口取证。

## 第一阶段，冻结可对比的走查环境

1. 核对当前提交、工作树状态、编译产物和求解器路径，记录实际启动版本、平台、DPI、主题、窗口尺寸、Qt／OpenGL 状态。开发构建和安装构建分别记录。仅在现有产物不足以验证当前代码时补构建。
2. 使用真实可见主窗口，准备正常桌面窗口和笔记本窄窗两种尺寸，再选高 DPI 与深浅主题作为覆盖变体。每轮从相同布局、数据和初始选择开始。首次使用走查和熟练路径分开记，避免用已知快捷键掩盖入口难找的问题。
3. 走查用副本，不打开或改写用户正在使用的项目。启动前验证临时、配置、缓存和数据路径都指向仓内。构建放在 `build/`，截图、隔离配置和结果证据集中放到 `artifacts/<run-id>/`。实测只使用手动工作流；可用 UI 自动化重放稳定步骤与采集控件树，记录人工点击时同样遵守真实选择与确认。

## 第二阶段，逐条走真实任务

每个箭头都是需要实测的检查点。记录入口在哪个菜单、工具栏、模型树或停靠页，点了什么控件、输入了什么值与单位、出现了什么窗口、下一步如何发现。验收以获得正确结果为结束。

| 任务 | 从起点到交付的走查节点 | 重点观察 |
|---|---|---|
| M1 从零完成线性静力 | 新建项目／文档 → 建立或导入杆梁／实体几何 → 选分析类型 → 选几何实体 → 设材料 → 设支承和载荷 → 网格（需要时）→ 检查 → 求解 → 看位移和反力 → 保存与导出 | 同一实体是否反复选，作用位置与单位是否就地可见，材料／支承／载荷能否快速定位，结果能否直接回到正确文档 |
| M2 修改已有模型再计算 | 打开已保存模型 → 查找某个材料或载荷 → 改指定参数 → 查看旧结果状态 → 复算 → 比较并撤销一次 | 区分草稿、接受值和旧结果，检查取消与 Undo、结果失效及文档切换 |
| M3 模态及时间响应 | 在已有模型上选分析 → 模态数量／方法／公差 → 求解 → 选择目标频率与振型；有时域分析时再设时步／总时长 → 读取目标曲线 | 默认值是否有来源，必填与高级是否分开，时步、输出采样、控制周期是否容易区分 |
| M4 网格候选与求解 | 选来源 → 设置网格尺寸／局部约束 → 生成 → 检查质量 → 接受候选 → 重绑定材料、支承、载荷和结果选择 → 求解 | 生成与接受的提示是否重复且是否表达不同后果，原模型／候选是否明显，边界重绑和质量问题能否定位 |
| M5 手动压电快速路线 | 打开已配置四杆 → 核对材料、端口、工作点和控制器摘要 → 求解确认 → 查看实时／终态结果 → 选端口和量 → 比较与导出 | 查找配置和结果要跨几层页签，工作台是否遮住模型，运行前能否看清对象、时长及控制策略 |
| M6 手动压电完整路线 | 选模型与成员 → 设材料和器件 → 设电极、传感角色和支承 → 探查模态及阻尼 → 设 LQR／MPC 和状态来源 → 设激励／时步／工作点 → 审阅配置并应用 → 保存重开 → 运行与导出 | 表格宽度、顺序依赖、跨页校验、重复录入、手动预览与审批的实际负担 |
| M7 运行与纠错 | 错选文档／缺支承／无效值 → 从提示跳到对应实体或字段 → 修正并重算。另测双作业、停止选中任务、恢复和查看历史 | 一眼辨认作用对象；保留未提交数据；失败、停止、恢复、旧结果的状态和下一步明确 |

优先实测 M1、M4、M5、M6；其余路径在改动前建立简短基线，并作为跨模块回归。未支持路径标为受阻，保留现象和证据。

## 第三阶段，保存每个环节的实际画面

同一 run 保留一份步骤台账、一套按任务／步骤编号的截图、必要的控件树和一个问题清单。每次进入新窗口或页签、改变表单状态、确认或出现错误时保存画面。弹窗保存整窗上下文及局部原图。连续重复输入可用同一组图记录起止状态，台账仍逐项写明。模型视口和结果用实际运行渲染；设计稿另行标注。

步骤台账记录以下字段：

```text
任务/步骤 | 起始选择和状态 | 实际菜单→窗口→控件 | 动作与输入（值/单位）
实际反馈及下一步 | 生效/草稿/取消状态 | 截图前/后编号 | 计时
点击/切页/弹窗/重复选择/重复输入 | 作用文档和结果身份 | 问题编号
```

统一计数口径：点击、键盘动作、字段输入、跨页／跨窗、滚动和回退单列；表单填写与求解等待分开计时。每条路径保留第一次完成记录和至少一次同条件复跑。等待期间记录是否能继续查看模型，以及焦点是否跳走。截取空态、禁用、校验错误、运行中、完成及旧结果这几类容易遗漏的状态。原图保留，标注使用副本；截图避免凭据和个人路径。

## 第四阶段，分析操作与视觉，再决定改法

- **任务逻辑。** 将步骤分为工程决策、必要校验、机械操作和补救。优先去掉重复选择、重复录入和仅为找入口而切换的窗口。批量应用材料、由模型选择带入目标、从错误定位到字段、求解完成自动关联结果都需用基线证明问题。
- **窗口安排。** 对照现有布局，评估模型树负责找对象、视口负责选对象、属性区负责改对象、结果区负责看同一作业，用户能否始终看到当前目标。编辑表单和视口需要同时可见时，优先试停靠属性区。长表和完整配方可以独立展开。阻断式对话框保留给真正需要先决策的事项。
- **信息密度与视觉。** 每屏核对首要操作是否明显、分组和阅读顺序、标签与值是否对齐、单位是否跟随字段、错误是否贴近源头、重要状态是否被日志压住、缩窄后是否横向滚动或裁切。优先统一字体层级、间距、表格列宽、图标加文字和状态色。截图并排比较同一任务状态。常用字段优先，复杂参数分组展开且可搜索或有稳定入口。
- **简化的安全边界。** 可以集中配置摘要、保留当前选择、自动关联同一作业。涉及改物理、覆盖原文件、接受网格候选、替换边界或停止多个作业时，确认必须说明作用对象和后果。保存、预览和应用语义须在 UI 上可区分。高级用户仍能核对完整数值与配方。

每条问题写清「哪一步、哪张图、实际后果、哪个控件拥有这段逻辑、最小改法、如何复测」。按误改或丢数据风险、任务阻断、重复成本、视觉一致性排序。优先挑 **一条跨多个任务的共性摩擦** 和 **一条压电专属摩擦** 做首批。对需重排窗口的变更，先用标注图比较小改与重组两种布局，再决定实施范围。

## 第五阶段，分批实施与验收

1. 先修导航和状态反馈。用真实任务验证当前模型、草稿、旧结果、作业和错误定位。
2. 再减少重复操作和整理表单。复用现有 Session、Host 和数值校验，保持现有文件语义、Undo 和权限边界。用同一输入、同一物理目标比较前后流程。
3. 最后统一布局与视觉。检查默认停靠、恢复布局、窄窗、高 DPI、键盘 Tab 顺序、焦点、禁用原因、深浅主题、标签可读性。控件操作与真实结果两类回归均保留。
4. 每批交付同尺寸前后图、操作路径差异表、指标、剩余问题和回滚点。以相同任务完成率、正确结果与无误操作为硬门槛。步骤减少、窗口减少及视口面积改善以基线实测为准，基线前不承诺百分比。覆盖取消、撤销、旧预览、切换模型、未保存修改和双作业。证据应允许第三人从同一起点重放。

执行时首先交付 **当前界面路径与问题图谱**，再根据图谱形成实际修改批次。可以打开编译好的软件走查；本次规划未启动 GUI、未采集截图或修改实现。

## 全流程覆盖与结束条件

M1–M7 是真实任务主线。执行时另建覆盖矩阵，按功能区域核对入口、状态和跨区域交接。不能以四条代表性主线的通过代替覆盖矩阵。

| 功能区域 | 必查操作与交接 |
|---|---|
| 启动与项目 | 首次启动、恢复默认布局、工作区与求解器设置、新建、打开、导入、保存、另存、重开、关闭未保存文档、跨文档切换 |
| 几何与视口 | 生成或导入、实体分组、树与视口联动、单选／多选／清选、拾取、显示隐藏、缩放旋转、常用编辑和撤销 |
| 物理与分析设置 | 分析类型与可用能力、材料、截面或厚度、支承、载荷、初始与环境条件、单位、常用默认值与高级项、压电器件及控制器 |
| 网格 | 生成、尺寸和质量反馈、失败重试、候选预览、接受、重绑定、模型变更后网格及结果失效 |
| 求解前与运行中 | 检查缺项、作用模型和版本、求解设置、提交、进度与日志、并行作业归属、取消、失败诊断、恢复及重新运行 |
| 结果与交付 | 变形和场图、振型、曲线、探针与反力、单位和图例、工件身份、控制开关对照、选择导出范围、CSV 和重新打开结果 |
| 跨流程交互 | 键盘焦点、滚动、窗口缩放、面板恢复、重复导航、错误定位、无数据与禁用状态、确认和撤销、无 Agent 的完整手动路线 |

覆盖矩阵以「任务 × 功能区域 × 关键状态 × 窗口条件」记录，避免机械穷举无效组合。每个实际暴露的入口至少做入口和作用范围核查；主线执行到结果，失败／取消／恢复及可能误改数据的路径做专项复现。按当前构建和模型支持情况标记为「实测通过、发现问题、受阻、不适用」，每项附步骤和证据或原因。阻塞若可绕过，先验证不受影响的路径，再回到阻塞项。最后按相同场景复测受改动影响的主线，并汇总尚未覆盖或未修复的条目。

## 连续执行与仓库整理

- **连续推进。** 获得执行指令后按环境确认、基线取证、问题排序、分批实现、回归、归档收尾的顺序连续完成。阶段产物和进度更新用于交接，默认不等待逐阶段确认。能安全解决的构建、布局或测试故障当场处理。仅在用户明确暂停、需要其提供无法替代的信息或授权时暂停依赖该条件的步骤，其余工作继续。
- **技能和台账。** 执行时使用 `planning-with-files` 管理独立的 GUI 优化计划，记录下一动作、覆盖矩阵索引和每批复测。复杂实现按仓库要求用 `astra-orchestrator` 拆分互不重叠的走查、实现和复核范围，主执行者负责同一版本上的整合验收。界面截图和控件树随步骤即时登记，避免另开重复报告。
- **每轮一个证据目录。** 截图、步骤表、运行日志、输入副本、临时目录和隔离配置按 run ID 放在 `artifacts/<run-id>/` 内。编译只用 `build/`，优先复用与当前源匹配的构建。同一批次保留一份入口索引，包含代码版本、构建路径、截图与测试凭据的映射。失败证据保留原样，重试使用独立编号。
- **每批清理。** 先等待本轮应用、求解及编译进程结束，再确认所有证据可读取。仅清理本轮创建且已确认无依赖的临时配置、缓存、试运行副本和废弃构建。保留可重放的输入、原始截图、决定性日志和当前验收构建。清理前逐项检查绝对路径、归属和引用，清理后用 `git status` 和产物索引核对。既有脏工作树、其他会话的产物、历史验收目录及活跃构建由原归属保留。
