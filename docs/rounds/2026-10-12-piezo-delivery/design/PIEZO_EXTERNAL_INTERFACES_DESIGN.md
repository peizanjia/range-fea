## 2. 一个连接模型，两类物理端口

```text
外部激励程序 ── d(t) [N / N·m] ──→ 已绑定的节点载荷映射 ──┐
                                                          ↓
传感读出 y(t) ←────── 原生 FE + 压电耦合 + 电极 + 支承
      ↓                                                   ↑
自编控制器 ── u(t) [V] ──→ 电压幅值/变化率限制 ──→ 作动电极
```

传感器物理量 → 控制器电气指令 → 压电实际机械作用 → 宿主结构与支承反力路径，必须由模型保持完整。连接端口只传信号，不代替器件布置或功率驱动。

- 激励提供器：返回命名扰动力/力矩；不读 FE 隐藏状态。
- 控制器：读用户选定的信号，返回作动电极的**绝对电压**。现有工作点增量在适配层显式换算。
- 同一程序可以实现两种角色，在一次连接中分两类端口注册；也允许分别连接两个程序。
- 仿真仍由本地 C++ FE 求解器积分。外部算法不负责推进 FE 时间，不要求使用 Python，不强制依赖模态降阶。
- 一阶接口只支持当前已存在的节点力/力矩和压电电压映射。面压力、基座加速度、温度激励、一般力作动器需要各自映射，不能把它们当成节点力或电压。

## 3. 用户操作

第五页“激励来源”提供：内置 / 时间数据文件 / Python 时间函数 / 外部程序。
第四页 Controller 增加 external；选定后显示“连接”和“信号映射”，不要求填写 LQR/MPC 矩阵。

两处复用同一连接卡：

| 模式 | 用户填写 | 生命周期 |
| --- | --- | --- |
| 启动外部程序（默认） | 可执行文件、分开的参数列表、工作目录 | 软件启动和关闭所创建的子进程 |
| 连接已启动程序 | 本机地址、端口 | 外部程序监听，软件主动连接；不关闭用户程序 |

默认本机连接。命令由文件选择器和参数表生成，禁止拼成 shell 命令。Python/C++ 可使用子进程；MATLAB 等持续会话可使用 TCP。首次连接的选择只是便利预设，两种方式使用相同消息合同。

操作：**选择程序/地址 → 自动列出端口 → 下拉映射模型信号 → Test connection → 完整预览并确认 → Run saved + 运行确认**。

Test connection 只做握手/端口检查，不推进控制状态。软件提供单独的示例测试器用于算法试算。预览列出连接身份、激励叠加、采样、限幅、超时和恢复能力，不增加碎片化确认框。模型未改时仍保持“运行＋一次确认”。

## 4. 传输与端口合同

采用 UTF-8 NDJSON，一条 JSON 一行；子进程 stdin/stdout 或 TCP 字节流承载。它是本项目的版本化协议，NDJSON/TCP 是通用格式/传输，不能称作已实现的 FMI 等行业协同仿真标准。

- 新协议标识 `range-external-io/1`，与旧 `protocolVersion:1/2` 的含义隔离。
- 串行请求/回覆；同一连接最多一个请求在途。接收端处理拆包/粘包、CRLF/LF，UTF-8 禁 BOM；默认每行上限 1 MiB，可有界配置。
- stdout 专用于协议，诊断写 stderr；TCP 诊断使用独立日志。无效 JSON、非有限数、重复字段/端口、未知操作或超限帧均失败。
- 握手绑定 runId、模型/配置摘要、端口清单及映射摘要、算法标识/版本、能力、种子；外部程序须返回算法身份。TCP 自报版本不能证明远端代码未变，结果须标注身份可信程度。
- 每条响应准确回显 runId、requestId、op；step/tick 和当前 accepted-state 摘要随步请求绑定。计数器和 ID 用字符串，避免 JSON 大整数跨语言丢精度。
- 内部端口 ID 稳定且由软件生成；界面只需选择可读名称。端口包含 quantity、unit、坐标系、正方向、absolute/increment、初始工作点、物理绑定。
- 默认 SI：N、N·m、m、m/s、m/s²、rad、rad/s、V、C。协议中力矩单位沿用当前代码的精确字符串 `N m`，界面可显示 N·m。单位必须匹配，不能默默转换或接受无单位值。
- 每个输出端口只有一个外部所有者。内置与外部激励可以显式相加，但预览必须列出贡献来源。控制命令不与其他控制器默默相加。

控制步消息示意（摘要字段在实际合同中为完整 SHA-256；此处为简写）：

```json
{"protocol":"range-external-io/1","op":"evaluate","role":"controller","runId":"run-1","requestId":"req-17","step":"200","tick":"20","time":0.02,"samplePeriod":0.001,"acceptedStateDigest":"sha256:…","state":{"integral":0.0},"inputs":[{"id":"tip.velocity","value":0.002,"unit":"m/s","reference":"increment"}],"previousApplied":[{"id":"patch-A.voltage","value":0.0,"unit":"V","reference":"absolute"}]}
{"protocol":"range-external-io/1","op":"evaluate","runId":"run-1","requestId":"req-17","step":"200","tick":"20","acceptedStateDigest":"sha256:…","outputs":[{"id":"patch-A.voltage","value":-2.0,"unit":"V","reference":"absolute"}],"candidateState":{"integral":0.000002}}
```

激励请求使用同一 envelope，role=excitation、inputs 为空，返回的 outputs 为载荷端口。请求明确指定采样时间及生效区间，不能用消息到达的墙钟时间代替仿真时间。完整握手和所有操作的机器可读 schema 属于实现交付项，以上示意不能当成现成 SDK。

## 5. 时序、状态与故障

### 离散控制

FE 时钟是唯一主时钟，控制周期 Ts=N×h。仅使用已接受的 FE 边界信号计算控制指令；求解试探点不触发外部状态更新。控制采样之间保持所请求电压，实际 FE 步施加值仍经过本地限制。

1. 在已接受边界 t_k 获取测量。带加速度/电荷直接馈通的测量使用该边界已记录的旧输入；不得用尚未计算的新电压构成同刻代数环。
2. 提供器返回请求电压和 candidateState。算法函数为 `evaluate(input, acceptedState) -> output, candidateState`。
3. 本地校验单位/端口，执行幅值及变化率限制，执行 FE 步。
4. FE 步成功后，保存真实 applied 值、FE 状态、候选控制状态和输入日志到同一 accepted/checkpoint 权威；失败则均不提交。
5. 下次请求包含 previousApplied，便于抗积分饱和；一旦候选被接受，后续保持步不得再次积分控制状态。

当两种角色共用连接时，固定调用顺序为：冻结本区间激励样本 → 若到控制采样点则计算控制候选 → FE 试算 → 一起提交。测量仍来自前一已接受边界，不因先取新激励而重算同刻测量。状态分别保存在 `excitationState` 和 `controllerState` 命名空间，各自采样才推进各自状态；不能在一个角色 evaluate 时暗改另一个角色。第一版不支持两角色共享可变隐藏状态。任何环节失败都不提交两者状态；已冻结的试算样本仍保留供确定性重试使用。

第一版要求算法显式输入/返回状态，SDK 封装 init/evaluate/close；不接受依赖隐藏可变进程状态的算法。连续 Simulink、硬件和不能回滚的状态机不在该合同内。后续若支持有状态端点，需另设 prepare/commit/abort 及恢复合同。

### 激励采样

- 文件和现有 force(t) 属于可按时间重复查询的确定性源，维持现有插值、任意时刻求值及验证语义。
- 新外部采样源第一版按 FE 边界采样并在区间零阶保持；采样周期可取 h 的整数倍。每个样本声明有效区间及绝对/增量参考。初始 d(0) 在计算初始加速度之前确定。
- 有状态激励发生器同样显式返回 candidateState；区间样本在试算前冻结，失败重试使用同一样本，成功后提交。随机源必须保存 RNG 状态/种子。
- 实时设备输入不可回放查询，必须先经过采样缓冲并固化到输入日志；第一版只承诺软件同步仿真，不直接读取硬件。外部慢程序让仿真等待，不改变 h，也不保证硬实时。
- 当前内置 MPC 有未来扰动查询、观察器也有已知力/直接馈通计算。对于无未来预览能力的流式源，必须在预览拒绝这些依赖，或实现并标注新的预测假设后再开放；不能凭当前值伪造未来力。自编控制器自行采用的预测假设由算法声明。
- accepted 结果认证与重放必须读取已固化的实际输入日志。不能在回放时重新调用外部端点来“证明”旧结果。

### 故障与恢复

默认任何断连、超时、错序、单位不符、缺失端口、NaN/Inf 都停止本任务，保留最后 accepted checkpoint；不默认为零，不自动重试可变操作，不自动重连续跑。

握手超时、单次响应超时、空闲等待分别管理；连接可以在 FE 计算期间长期空闲。连接卡默认建议握手 30 s、请求 5 s，均可设置；SDK 服务端不能用单次响应超时关闭正常空闲连接。取消可打断等待并有界清理软件拥有的子进程。

现有内部 PiezoNumericTransport 的每请求总期限为 60 s。新增外部等待必须纳入统一 deadline/cancel 预算并向内层传递，或调整宿主期限；不能配置一个超出宿主总期限而实际永远无法完成的外部超时。多个角色的串行请求也应计算在同一操作预算内。

恢复先验证算法/模型/配置/映射身份、日志前缀及 acceptedState，再以新连接握手恢复；不允许把其他版本的算法状态接上。外部身份不能验证时拒绝断点续跑，允许作为一个明确的新实验启动。已完成日志可以独立离线回放。

日志区分 requested / limited / applied，记录超时及协议故障。程序依赖、权重文件和算法版本必须进入本地身份清单；TCP 身份由外部声明的事实须保留。设计不增加硬件安全保证。

## 6. 三维实体的原设计位置

三维实体在理论上可以作为结构宿主并贴压电片；当前工作台却只接受受限的轴向杆、平面梁和平板后端。一般结构求解器的体单元能力不能等同于此处的压电耦合能力。

后续可实现：HEX/TET 结构体 + 表面贴片/独立压电体，建立共享节点或经验证的 tie/MPC/投影连接。必须处理实体平移自由度与贴片运动学、局部轴/极化、厚度偏置、质量刚度、机电互易、电极和反力路径；不能给实体表面几个节点加电极名称就算完成。

本次命名端口与单元类型解耦，将来扩展 FE 物理映射时外部算法不必改协议。实体贴片仍须通过网格收敛、耦合基准及能量/互易验证后才能开放。

## 7. 实现顺序及验收

1. 冻结 schema 与最小 Python/C++ SDK：复用现有有界进程传输，新增独立协议命名空间；使用标准 TCP bridge 接同一 schema。
2. 接入 excitation provider：节点力/力矩、输入日志、确定性回放；保留已有 force(t)。提供双通道正弦和有状态扫频示例。
3. 在现有 force/propose/postFE 桥接上加入 external controller，复用既有原生限幅和 accepted 状态；同步更新两种压电后端的预览、身份、checkpoint、结果认证和缓存失效规则。
4. 工作台连接卡及端口映射，提供 Python/C++ 子进程和 MATLAB TCP 控制器示例；用户算法只处理物理信号和状态。
5. 运行真实模型、故障注入、恢复、安装构建和 GUI 验收后再交付入口。

| 验收项 | 必须提供的证据 |
| --- | --- |
| 外部激励正确性 | 相同采样/保持规则的内置、文件和外部源产生相同 FE 响应；力/力矩方向与量纲验证 |
| 外部控制正确性 | 与等价内置速度反馈逐步比较 requested、applied、传感及 FE 响应；覆盖轴向与层合 |
| 协议健壮性 | 拆包粘包、空闲等待、超长帧、坏单位、缺失/重复端口、错 run/request/step、超时和退出 |
| 多速率与因果性 | N=1 / N>1、t=0、直接馈通、保持区间、限幅及实际输入回传 |
| 状态事务 | FE 失败/取消不多更新一次积分器或 RNG；重试同一样本，恢复与连续计算一致 |
| 双角色同时运行 | 同一连接和不同连接，激励/控制各自多速率；第二角色失败或 FE 失败时全部不提交；恢复不重复推进任一状态 |
| 激励能力边界 | 无未来预览源不进入依赖真实未来力的内置预测/认证路径；日志回放不调用原端点 |
| 身份与保存 | 算法/权重/映射变化使旧预览和恢复失效；保存重开后端口保持 |
| 操作成本 | 首次自动发现及下拉映射；未修改实验只有运行预览一次确认 |

数值容差按各模型尺度和既有物理验证要求预先确定，不能为通过新接口临时放宽。本文不修改冻结的 12 阶段/36 项验收，也不将此设计或局部测试作为最终交付完成。

长程性能尚未资格化：当前输入历史在检查点复制和前缀验证存在随历史增长的额外开销；合成容量测试不能替代长时间真实 FE 运行基准。尚未完成最终同源安装包、首次配置至结果导出验收，也未改变 `PIEZO_CONTROL_DELIVERY` 原有 12 阶段/36 项验收状态。
