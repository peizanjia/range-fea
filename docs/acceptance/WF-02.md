## 失败修复与契约细节

- Frozen project snapshot 实际读入 solver input，不能只把 A 的 ref/hash 标在 B 的 live body 上；读取前后 SHA、受管理路径、runtime stamp 均验证。
- Host 与 manager 的 sourceStamp 都包含 documentId/revision/sessionEpoch；共享 validation 在 host 的 Session 锁外运行，前后重新核对版本、project/draft、交互和 legacy job 门槛，避免重入互斥锁误报 stale。
- `RProgress` 的结束回调消息可以是 `Done`；只要求 fraction 事件保留 phase message，结束仍验证 phase/seq/protocol/finish fraction。
- nullable boundary axis 以 `json-text/v1` 无损审计编码保留 null，与零值轴分开；严格 InteractionRecord v1 payload 未放宽。Session/GUI 解析日志并比较原规范参数，旧记录/日志读回与幂等保持兼容。
- Result raw logical SHA 与 terminal MODEL SHA 分开。worker 在 readback 前后和实际读取绑定中验证完整 MODEL/LINK 链；registry 固定 `resultSourceBinding`，host 打开/复用/加载后再次比较。只修改 terminal 而保留 LINK 原字节也拒绝，registry 原证据不被更新覆盖。
- Duplicate native source 可能按项目目录规则 detachAsCopy 并清除 loaded binding；host 从同步 addModel 的新增槽位取得新 runtime UUID，不误报已经创建的结果副本为失败。
- 三项旧测试仅更新当前 writer 的 1.3.18 断言；真实 17/16 及更早 setup 兼容夹具保留。未删除失败断言、削弱 legacy busy gate 或把不完整结果改成成功。
- 控制配置只读上下文保留 uint64 seed 的十进制字符串，conditioning 独立有界分页；205 通道、INT_MAX offset、过期游标、4096 上限及超长 controllerId 均有反例。它只验证原生接受配置，不宣称物理映射或运行中的控制器可用。
- 编辑器以当前渲染的 runtime UUID 集合恢复焦点/光标/选区，过滤无文档切换的伪选择刷新。Windows 实际鼠标选文档、Ctrl+A/Backspace 输入空草稿、只读查询和另一文档刷新后保持焦点/文本/接受版本；`1e-` 草稿的反向 `e-` 选区与 cursor=1 在重建后保持。测试使用当前 itemWidget，避免退休控件；真正切换文档仍不恢复旧焦点。
