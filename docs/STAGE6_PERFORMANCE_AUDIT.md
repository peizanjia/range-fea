# Stage 6 动力学与控制性能稽核

更新时间：2026-09-24。状态：源码稽核与可复现基准说明；**不是**性能优化完成证明。以下结论针对当前固定网格、固定步长结构动力学路径。没有把测试的诊断计时冒充已验证的并行加速。

## 1. 热路径与已并行范围

| 阶段 | 当前实现与成本 | 并行边界 |
| --- | --- | --- |
| 时间步准备 | `RSolverGeneric::run()` 每个动态步均调用 `initialize/recover/prepare/solve/process/store`。`RSolverStress::prepare()` 在首步还递归准备一次 `t0` 的初始载荷；此后仍重新生成方程信息、变量/载荷向量，并组装固定 `M/K`。 | 点、线、面、体单元装配使用 OpenMP 分实体循环和线程私有矩阵/向量缓冲；按矩阵行合并也并行。实体层循环、异常临界区、缓冲分配/合并仍有同步和内存带宽成本。 |
| 约束约化与不变性检查 | MPC 路径先构造密集零空间表，再扫稀疏矩阵实现 `Tᵀ M T`、`Tᵀ K T`；其代价取决于每个物理自由度对应的非零约化权重，不宜笼统称 `O(nnz)`。`solveStructuralDynamics()` 每步还双向逐项比较参考与新矩阵，并比较约束映射。 | 这些循环目前没有显式 OpenMP；固定矩阵仍被重新组装后校验，不能仅凭积分器缓存认为整步算子已缓存。 |
| 控制采样/力 | 控制器在接受态边界调用一次；执行器映射预计算约化权重，施力及单通道功率是稀疏权重遍历。控制命令变化时 `refreshAcceptedForce()` 另解一次质量矩阵，以实现区间起点的零阶保持阶跃。 | 控制器不进入单元装配或 CG/GMRES 内迭代；进程外请求按步串行等待。它适合控制频率低于求解器内迭代的路径，但外部 API 延迟会直接拉长墙钟时间。 |
| 时间积分与线性求解 | `RStructuralDynamicsIntegrator::operatorForStep(dt)` 对完全相同的固定 `dt` 缓存有效稀疏矩阵。每次 `solve()` 仍新建 `RMatrixSolver`，并做残差检查。中心差分当前仍解含质量/阻尼的线性系统，不是对角质量、零迭代的纯显式路径。 | `RMatrixSolver::solve()` 每次构造预条件器，并刷新/核对 CSR 缓存的值和索引；CSR 缓存不会在每次 CG/GMRES 内迭代重建。CG 有 OpenMP 向量运算和归约，但每迭代有 barrier；GMRES 还含正交化归约、`critical` 与串行小矩阵操作。Jacobi 预条件器构造逐行串行，块 Jacobi 构造按块并行。OpenMP 线程数报告只是探测，不等于持续占用。 |
| 事务、结果与磁盘 | `RSolverGeneric::run()` 动态步开始复制整个 `RModel` 和共享数据；`RSolverStress::beginStepTransaction()` 还复制矩阵参考、运动/支承/控制状态等，用于失败回滚。`process/store` 每步更新节点和变量；`RModel::write()` 只在输出频率命中或最后一步调用。 | 深复制、逐步结果更新、序列化/磁盘写入尚无专门并行路径。减少输出频率只能减少磁盘写入，不能消除每步复制、组装和结果更新。 |

源码依据：`../src/range-solver-lib/src/rsolvergeneric.cpp`、`rsolverstress.cpp`、`rstructural_dynamics_integrator.cpp`、`rmatrixsolver.cpp`、`rmatrixpreconditioner.cpp`、`rparallel_execution_context.cpp`、`rstructural_control_force_map.cpp`。稀疏矩阵缓存目前采用每线程缓存并在每次新 `solve()` 核对模式/数值；本稽核不把其并发安全视为已获完整集成验证。

## 2. 复现现有基准与正确性检查

在仓库根目录 PowerShell 执行。首次运行先完成 Release 构建；不要在另一进程同时修改或构建同一 `build/vs2026` 目录。

```powershell
cmake --build build/vs2026 --config Release --target tst_structural_dynamics_parallel_repro --parallel 4
ctest --test-dir build/vs2026 -C Release -R '^tst_structural_dynamics_parallel_repro$' -V --timeout 180
```

该测试的定义在 `../src/range-solver-lib/tests/tst_structural_dynamics_parallel_repro.cpp`：32 和 384 个 `TRUSS1` 单元、10 个 Newmark 步、串行/固定 2/固定 4 线程，每组合重复 3 次，打印 `BENCH elements=...` 的中位耗时、`serial/this`、线程请求/应用/探测值、降级与误差容限比；对节点与约化 `q/v/a`、能量和 checkpoint 作容差比较。测试**没有**最低加速比断言。其无磁盘模型输出，也没有控制进程和复杂 MPC/壳/实体，因此不能外推为真实大模型、外部控制、8 线程或 I/O 性能。

2026-09-24 主 `build/vs2026` Release 独立运行一次上述 CTest（每组合内部 3 次取中位）所得：

| TRUSS1 单元数 | 串行 | 2 线程 | 4 线程 | 4 线程相对串行 |
| ---: | ---: | ---: | ---: | ---: |
| 32 | 24.726 ms | 68.365 ms | 83.695 ms | 0.295×（变慢） |
| 384 | 175.868 ms | 158.218 ms | 144.151 ms | 1.220× |

两个规模的节点及 checkpoint 数值比较均通过；4 线程实探测为 4，但并行归约未声明逐位确定性。此数据只是一台主机上的小样本，不是普遍的加速承诺；更大模型、控制进程和 I/O 尚未测。原始输出保留在本地 `build/vs2026/Testing/Temporary/LastTest.log`（忽略的构建产物，不入库）。

性能测量应单独运行该测试，不与 `ctest -j` 多任务同时争用 CPU。收集 OS/CPU、构建配置、OMP 运行时、模型规模、线程报告、每步/全程耗时、中位数与离散度、峰值内存、迭代次数/残差及数值误差。用至少一个大于 384 单元的代表性梁/面/体模型补 1/2/4/8 线程测量；同一模型、同一固定 `dt`、同一输出频率、同一求解精度和控制输入才可比较。

## 3. 优化优先顺序与守门条件

1. **先加分段计时与内存指标**：分别记录准备/装配、约化与矩阵比对、控制进程等待、有效算子/预条件器、Krylov 迭代、结果处理、事务复制、序列化/磁盘。计时与测试仅用于诊断，避免把 `parallelReport.actualThreads` 当加速证据。
2. **固定算子复用**：在模型、网格、材料、约束和支承映射冻结的前提下，缓存已约化的 `M/K/C`、方程书、约束映射与不变载荷。时间变化载荷单独更新右端；若材料/几何非线性、接触或热-力状态使矩阵变化，必须使缓存失效或走重新装配路径。现有每步全矩阵比较可在可靠 revision/依赖签名建立后移出热路径，不能直接删掉验证。
3. **线性算子/预条件器重用**：固定 `dt` 下有效矩阵缓存已经存在，但预条件器每次重新构造、CSR 每次刷新仍有成本。重用需要明确矩阵所有权、版本和线程隔离，变更后用并发矩阵测试及受控续算误差检查；不能靠裸指针地址判定矩阵不变。先验证基准显示这段是瓶颈，再考虑更复杂的预条件器或矩阵-向量内核。
4. **减小接受步事务复制**：以修改日志或 copy-on-write 替代两层全量快照之前，必须保持“试步/写出失败后恢复上一接受态”的原子性，包括控制器状态、延迟/噪声状态、功账、模型输出与共享数据。磁盘工件与审计日志目前没有跨文件原子提交，不应宣传为已有完整事务。
5. **按规模设计并行**：小网格的 OpenMP 启动与归约可能超过计算量；大网格再衡量线程私有装配缓冲内存、NUMA/带宽、CG 同步、GMRES 正交化及输出 I/O。优先做单任务内多线程与数值一致性，再考虑多个求解任务并行，避免线程过量订阅。

退出指标不是“达到预设倍数”，而是：同一个正确算例与重启/失败路径一致；列出各阶段耗时/峰值内存及线程降级；以多次中位数和离散度呈现有/无控制以及不同线程数的 A/B；若某规模变慢，明确记录而不隐藏。
