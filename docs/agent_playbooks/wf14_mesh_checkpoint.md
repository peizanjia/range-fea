# WF14 detached mesh candidate checkpoint

2026-10-09. This is a bounded implementation checkpoint, not WF14 acceptance. Root owns registration, the isolated worker process, runtime/source snapshot hashes, job identity/deduplication, GUI/CAS acceptance, native publication/recovery, installation and end-to-end execution. No native build, QtTest or mesh generation was run by this implementation agent.

## Frozen service contract

`RMeshCandidateService` in `range-application-lib` has `preview(const RModel &, const QJsonObject &)`, `generate(const RModel &, const QJsonObject &, const std::atomic_bool *cancel = nullptr)` and `capabilities()`. `MeshCandidate` returns `valid`, `code`, `message`, detached `candidate`, `normalizedArguments`, `sourceGeometrySha256`, `postGeometrySha256` and `report`. A successful preview has no candidate mesh; failures/cancellation clear the candidate and post hash. The service holds no Session, live model, file path, publication authority or executable callback. Caller must freeze/copy the source before invoking it; `const` does not make concurrent mutation of the same object safe.

Arguments have exactly four fields: `unit: m`, `volumeUnit: m^3`, finite `maxVolume` in `[1e-15, 1e18]`, finite `radiusEdgeRatio` in `[1.2, 2.0]`. Unknown/missing fields, algorithm names, free TetGen parameter strings, callbacks and size functions are rejected. Effective numbers are normalized to six significant digits because the existing generator serializes `QString::number` with that precision; normalized values, not unpassed extra precision, drive estimation and output volume checks.

Source is one convex, connected, genus-zero, outward, closed TRI1 outer shell with 4..5002 nodes and 4..10000 facets. Every facet belongs to exactly one uniquely named surface with a valid stable group ID. Existing point/line/volume groups, concave or inward geometry, holes, mixed orientation, disconnected/pinched shells, coincident nodes, duplicate/degenerate triangles and heterogeneous surface materials are rejected. Supporting-plane checks restrict the first entry to convex shells; coplanar separating-axis checks reject interior facet overlaps. This is not a general CAD/intersection or arbitrary closed-surface meshing capability.

The first scope has exactly one volume region, named `WF14 single region`, with the identical material shared by the input surfaces (or an explicitly empty material). Surface names, stable group IDs and materials remain only after the returned marker groups and independent per-input-facet subdivision coverage are verified. The new volume group has a new region identity. Multi-region/material inference is unsupported. No nearest-node cross-mesh mapping is used.

Resource guards: source coordinates finite within +/-1e6 m; shell length exceeds 1e-9 m; triangles and volume exceed scale-relative resolution limits; bounding-box volume / backendMaxVolume <= 2000; returned nodes <=10000 and elements <=50000; node/facet verification <=20 million pairs. The fixed backend volume target is 0.5 * normalized requested maxVolume, itself normalized to six significant digits, to allow headroom for TetGen's final smoothing/improvement. Admission uses this stricter target, and the independent final acceptance gate still enforces the normalized requested maxVolume. Both values and the fixed factor are reported; one existing generator invocation is used, without iterative retries or silent parameter retuning. These are conservative admission/output bounds, not an in-process TetGen allocation bound or universal final-volume guarantee. An isolated worker must apply time/memory limits and process termination for hard cancellation. Cooperative cancellation is checked before/after TetGen and inside validation; the generator call itself cannot be interrupted cooperatively.

## Independent verification and invalidation

Validation is newly authored algebra over public node coordinates/connectivity: edge incidence/orientation and vertex-link topology, supporting planes, shell volume and first moment from oriented triangles, positive TETRA1 determinant and finite volume, circumradius/shortest-edge quality, tetrahedral face incidence, physical boundary membership, bounds and centroid, same-marker triangle-intersection areas, and per-source-triangle area totals. TetGen's default `mergefacets()` can remove a coplanar diagonal; independently authored planar convex clipping permits that change while requiring each output facet area and each source physical facet area to be fully covered with the same marker. Total volume agrees with independent shell integration to relative 1e-8; centroid agrees within 1e-8 of the bounding diagonal; maximum element volume obeys the effective requested maxVolume to relative 1e-8. Circumradius/edge extrema are measured independently and reported; no universal backend quality guarantee is implied solely by its requested quality setting.

Every output node and element receives a strictly fresh stable physical ID above both source and generator-produced IDs. Public `setNodePhysicalId` / `setElementPhysicalId` also advance the internal allocator; pre/post headroom checks reject overflow. This explicitly handles TetGen export preserving old array slots when resizing. Surface group IDs retain identity only under the verified marker/coverage proof.

The private candidate clears full ProblemSetup, time/monitoring state, BC/IC/environment conditions, results, entity variable data and derived fields before and after generation. The report lists invalidated control/sensor/actuator/constraint/coupling/prescribed motion/condition/restart/result/modal/ROM/monitoring/derived setup kinds, `bindingState: REQUIRES_REBINDING`, `rebindingRequired: true` and `crossMeshMappingAvailable: false`. Source data remain untouched. Root must enforce this state before solver execution and retain the original document/results independently; clearing private candidate data does not itself implement recovery or an execution authority gate.

Report hashes bind source geometry, source surface labels/materials, normalized arguments, effective backend parameters, post geometry and quality/volume metrics; `reportSha256` hashes the report before adding its own field. Root must additionally bind full source snapshot, environment/runtime identity, job and candidate artifact bytes. Geometry fingerprint alone is not a full model snapshot hash.

## Dependency and originality record

The meshing algorithm is the existing upstream dependency path `RMeshGenerator::generate(RMeshInput, RModel&)` -> `RTetGen::importModel` -> TetGen `tetrahedralize` -> `RTetGen::exportMesh`. Import assigns negative surface-position facet markers; export uses marker magnitudes to reconstruct surface groups. The service verifies that correspondence independently instead of trusting retained group names. Fixed `RMeshInput` enables linear volume/quality mesh with configured volume/radius ratio, tolerance 1e-10, no reconstruction/size function/output edges/result interpolation/free parameters. Existing `RModel::generateMeshTetGenInputParams` emits the backend parameter line; it is recorded rather than authored as a user-controlled string.

No CAD kernel or meshing algorithm is newly claimed. Public API reuse, topology/coordinate checks and analytic tetrahedron/unit-cube fixtures were authored for this candidate contract. Upstream Range licensing/provenance remains applicable; TetGen is an existing AGPL/commercial dependency. This is not a clean-room or independent mesher claim, nor a licensing conclusion for the complete product.
