# 中断恢复与保存核对

适用于当前开发版本。WF-05 正在整体验收；交付状态以 `workflow_delivery_plan.json` 及验收记录为准。

## 从中断的计算继续

在 Workflow 任务列表选择 `interrupted` 任务，点击 **Check interrupted recovery**。程序区分可恢复、需重算、待核对和冲突；发现输出文件本身不代表任务已经成功。

可恢复时，新预览显示原尝试、固定目标、每条 active/passive 轨迹的接受步和剩余步数及检查点哈希。确认该预览后创建新尝试。原逻辑任务身份和旧日志保留；已经校验完成的轨迹复用，只继续未完成部分。both 任务需要两条轨迹和独立比较都完成才成功。

原生 GUI 作业在 **Document FE output** 选择中断任务，点击 **Check selected native recovery**，查看完整接受检查点，再批准该次原生恢复。恢复输出属于独立尝试，原文档不被恢复过程覆盖。原生 GUI 首版仅对受支持、未启用外部控制的 Newmark 结构动力学提供周期检查点；没有受支持检查点的模态、混合任务和控制入口会明确返回需重算或待核对。Workflow 后端另支持已验证的杆/梁 active/passive 控制恢复。

旧批准只在原实例内有效。重开后不会自动执行旧提案，不能复用旧批准令牌。源模型、控制程序、增益、软件运行时或检查点发生变化时，需要先处理冲突或重算。

## 数据保护范围

受支持计算在完整接受事务后，最迟每 10 个接受步或 1 秒仿真时间（先到者）保存检查点。该频率独立于显示频率。检查点包含 q/v/a、控制和支承状态、功账、版本及来源证明；到期写入失败会停止继续接受步骤。恢复显示实际选择的接受步和回放范围，历史帧不冒充新尝试产生的帧。

保护范围不等于界面所有尚未保存的内容。命令宿主持久接受快照可恢复；pending 数值草稿、未同步内容及传统未纳入接受入口的修改可能只在内存中。查询中的 `recoveryProtection` 明确指出范围。

保存先登记意图并绑定暂存字节，再逐文件发布 MODEL/LINK，最后核对目录与审计。多个文件不构成一个原子事务。部分发布、外部替换和关闭记账失败保留为待核对或冲突；核对不会覆盖用户的新文件。

每个文件复制完成后、原子提交前，再核对原目标是否存在及其哈希；发现外部变化即停止，保留此前已发布部分和外部替换内容。这不是操作系统级比较替换：不遵守项目锁的外部程序仍可在最后一次核对与重命名之间竞争。并行编辑时应先关闭外部写入，再处理冲突。

## SDK

```python
qualification = client.recovery(job_id)
if qualification["eligibility"] == "recoverable":
    preview = client.preview_recovery(job_id)
    # 由可信调用方审阅这个固定检查点和范围，再批准。
    approval = client.approve(preview)
    attempt = client.execute(preview, approval)
    finished = client.wait(attempt["jobId"])
```

底层接口为 `job.recovery.query` 和 `workflow.recover`；后者参数是原 `jobId` 和最新 `qualificationSha256`。GUI 原生作业使用 `native.job.recovery.query`，新的 `analysis.recover` 预览绑定 `jobId`、`checkpointSha256` 与固定 `remainingSteps`。这两个作业域分别保留自己的不可变输入和来源。

`operations.query` / `operation.query` 查询持久操作事实。重复幂等键返回原观察；同键不同请求拒绝。已知拒绝也保持原拒绝，新的执行需要新请求。未观察到的意图保持未知，不能通过重发同一键假设操作没有发生。

## 重开、迁移和冲突

工作区 v1 首次重开迁移为 v2，保留作业和审计，删除旧持久批准令牌。旧程序不能直接读取 v2；不要编辑版本号或复制旧批准以降级。继续使用旧程序时应使用迁移前独立备份，并把它作为旧的只读历史，不合并两份正在写入的工作区。

如果返回冲突，保留原工作区和尝试目录，查询具体来源及哈希；修复运行环境后重新核对，或者以明确的新来源重算。坏日志、坏检查点、协作锁和外部替换不通过删除旧结果来处理。旧工作区没有完整检查点时，成功后的普通续算仍是独立能力，不能据此把崩溃任务判为已恢复。

原生恢复按原项目和逻辑作业加跨进程锁，并保留唯一后继。提交新尝试后，旧入口返回待核对及 `latestAttemptJobId`；继续中断计算应选择该最新尝试，不从祖先检查点另开分支。若新恢复在排队时被取消，当前版本保留已取消后继，原入口不会重新提交。查询取消事实及原始受保护输入，再明确创建新的重算作业；不要改写状态或删除后继来绕过保护。
